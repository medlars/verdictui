# VerdictUI — Deliberate Non-Decisions (no.md)

Numbered list of things we deliberately did NOT do, so future sessions stop re-litigating them.

1. **No private SwiftUI API in the core path.** `_viewDebugData()` / `SWIFTUI_VIEW_DEBUG=287` / AttributeGraph interception are powerful but break across OS releases. They may ship later as an *optional* adapter target, never as a core dependency. Decided 2026-08-04 (three-option deliberation during product design; public-API instrumentation chosen as the spine).
2. **No external AX scraping as the primary channel.** `AXUIElement` trees depend on developer labeling and permissions; they are the *cross-validation* channel (middle loop), not the source of truth. Decided 2026-08-04.
3. **No web backend in Waves 1–9.** The contract (CLI/MCP verbs, verdict schema) is designed platform-agnostic from day one, but the web adapter is deferred until the SwiftUI backend is proven — web engines already exist free (CDP/Playwright); SwiftUI is the differentiated wedge. Decided 2026-08-04.
4. **No proprietary licensing for the engine.** Open-core: MIT engine for adoption, monetize the hosted workflow layer later. Decided 2026-08-04 after competitive research (all serious competitors are free; closed dev CLIs get zero adoption).
5. **No CoreGraphics types in the kernel.** `Rect` is hand-rolled so `VerdictUIKernel` compiles on Linux CI for pure-logic tests. Decided 2026-08-04.
6. **No path-only `TreeDelta`, and no `relocated` case.** The Wave 1 plan sketched `added: [NodePath]`; the shipped `TreeDelta` uses `added: [NodeAddition]` carrying the added subtree, and concretizes the `moved`/`changed` tuples as `NodeMove`/`NodeChange` structs (tuples are not `Codable`). Reason: `TreeDiff.apply(_:to:)` must reproduce the after-tree exactly — that round-trip is the property-test invariant and the reason Wave 7 can ship a delta instead of a full tree; a bare path tells an agent that *something* appeared but not what. For the same reason a re-parented node is reported as a removal plus an addition rather than a `relocated` entry: structure then always replays exactly. An explicit `relocated` case can be added later as a non-breaking hint. Decided 2026-08-04 (Wave 1 Task 2).
7. **No `warning` finding emitted by the harness when the host size is clamped.** The Wave 2 plan's risk list said "cap by explicit viewport, emit a `warning` finding when clamped"; the shipped `OracleHost` caps and exposes `wasClamped` as a fact instead of synthesizing a finding. Findings are the kernel's output and the kernel is deliberately blind to how a tree was produced — a harness that injects findings into a verdict it does not own would break that boundary. The caller that assembles verdicts (Wave 6's CLI, or any consumer of `DemoReport`'s shape) reads `wasClamped` and attaches the warning there. Clamping is never silent: `OracleHostTests` pins the flag on both the capped and the nonsense-size paths. Decided 2026-08-04 (Wave 2 Task 3).
8. **No `accessibilityReduceMotion` pin in the oracle host.** The plan's Task 3 listed `accessibilityReduceMotion = true` among the environment pins; it cannot be written — the `EnvironmentValues` property is get-only, so there is no `WritableKeyPath` to pin through, which the compiler states plainly. Wave 2 renders no animations, so no tree depends on it; Wave 3, which drives animations deliberately, controls them with `Transaction(animation: nil)` instead of asking the system to. Documented on `View.verdictPinnedEnvironment()` ("the one pin that could not be made"), which is where all seven pins that *could* be made live. Decided 2026-08-04 (Wave 2 Task 3).
9. **No partial JSON from a failed demo run.** When one scenario in `DemoReport.verdicts()` times out, the already-computed verdicts for earlier scenarios are discarded and the run fails with exit code 1, the error (naming the scenario) on stderr, and *nothing* on stdout. The alternative — printing the verdicts that did settle — was rejected because a partial array parses cleanly and reads as a smaller catalog: a consumer diffing against six baselines would see three "missing scenarios" instead of one named failure. Stdout's contract is binary: one complete document, or empty. Decided 2026-08-04 (post-Wave-2 audit, correctness reviewer finding P1).
10. **No test for a probe that wraps zero subviews, and no rewrite to avoid needing one.** `ProbeLayout.measure` ends in `union ?? .zero`. Two attempts to reach that fallback — `EmptyView().probeLayout(id:)` and an empty `ForEach` — both produced *no measurement at all*: SwiftUI elides empty content before a custom `Layout` is instantiated, so `sizeThatFits` is never called and there are no subviews to be zero. The branch is unreachable through the public modifier. The first attempt at resolving that replaced the optional accumulator with `reduce(into: .zero)`, which makes the empty case an identity element instead of a branch — and was reverted, because it puts a `max(0, _)` on the **single-subview** path, where `max(0, -5)` and `max(0, .nan)` are both `0` in Swift (verified, not assumed). A wrapper documented as returning its subview's answer byte-for-byte would then silently rewrite a negative or NaN dimension. Trading an unreachable `??` for a reachable misstatement is a bad trade, so the fallback stays and is documented as unreachable at the call site. The general rule: prefer deleting a branch no test can enter, but not when deleting it changes behaviour on a path tests *do* cover. Decided 2026-08-04 (post-Wave-2 audit, test-quality reviewer finding #4; reverted same session).

11. **No separate `Tests/VerdictUIBenchTests/` target.** Wave 3 Task 6 specified the benchmark harness as its own test target; it shipped as `Tests/VerdictUIProbeTests/HarnessPerformanceTests.swift` instead. Reason: the benchmark measures `Harness.perform()`, which needs `OracleHost`, `VerdictScenario`, `ProbeAction` and the demo scenarios — the whole probe surface the existing target already imports. A separate target would duplicate that dependency set, add a second place for the `@MainActor`/autoreleasepool test-host boilerplate to drift, and buy nothing, since `swift test --filter HarnessPerformanceTests` already selects it precisely and `stage_runtime_bench` filters on exactly that name. The plan's own reason for a separate target was isolation from unit-test runtime, which `--filter` provides without a target. `docs/implementation-plan.md` still names the target that was not built, which is how this went unrecorded until the Wave 1–3 audit found the dead path. Decided 2026-08-06 (Wave 3 Task 6; recorded retroactively during the Wave 1–3 audit).

12. **No test pinning `timing.settleMs` on the settle-TIMEOUT path.** The audit found `perform` assigning the *requested* timeout to `settleMs` on that path — a budget reported as if it were a measurement — and the source fix (measure with `ContinuousClock` across the `settle` call, on both branches) is committed. What is *not* committed is a test that discriminates the two, and three attempts failed for the same reason each time: the assertions that seemed to separate a measurement from a budget (`> 0`, `<= elapsedMs`) are satisfied by both. A fourth attempt compared against the budget directly and still passed under mutation, because `.custom("mover")` does not reach a settle bound by `perform`'s timeout at all — the measured value was 3000 ms against a 120 ms budget, i.e. the test had been exercising a different path than its name claimed since the first version. Rather than keep a green test that proves nothing, it was deleted. The honest state: the fix is right and is covered indirectly by `testSettleMsIsMeasuredNotAssumedOnTheSettlePath` (happy path) and `testSettleMsIsZeroWhenNoSettleRan` (no-settle path), while the timeout path is unpinned. Closing it needs a fixture whose settle genuinely runs to a caller-supplied deadline — tracked in CTS-8DDE6D09. **The rule this cost: an assertion that both the correct and the incorrect implementation satisfy is not a weak test, it is not a test.** Decided 2026-08-06 (post-audit sweep).

13. **No p95 assertion in `stage_runtime_bench`, and no widening of the SLO to restore one.** The stage gated p95 against SLO 1's 100 ms until 2026-08-07, when it blocked the PM at p95 105.51 ms on a p50 of 49.09 ms — while two isolated runs of the same commit gave 58.43 and 77.01 ms. `HarnessPerformanceTests` had **already decided this**: it records p95 and asserts p50, because p95 moves 56.7 → 106.7 ms purely with contention while p50 sits at 49.6–51.2 ms in every context measured. The decision was made in the test and reversed one level up by a consumer that re-derived its own verdict from the same printed line. The tempting fix — raise the budget until it stops failing — was rejected: a threshold moved to silence a failure is a silencer (SE Principle 11), and the number was never wrong; the *statistic* was. The stage now gates p50 at 70 ms and reports the tail as evidence, verified live on a run reading p50 49.93 ms / p95 101.99 ms — one the old gate would have failed while the median sat at half budget. **The general rule: when two layers both judge the same measurement, only one of them owns the claim. A consumer that re-derives its own verdict silently outvotes the decision, and no test sees the disagreement unless something compares the two thresholds** — which is why `test_the_gated_budget_agrees_with_the_swift_test` parses `performP50BudgetMs` out of the Swift source. Decided 2026-08-07 (CTS-9686A8BB).

14. **Never run any command against the working tree while `scripts/mutation-check.py` is sweeping.** The harness edits source files in place for the length of the run and restores each one after. A concurrent write — a `pytest` invocation, a `git checkout`, an editor save, another probe — corrupts both the sweep's verdict and the probe's, and the corruption is **silent in the expensive direction**: the harness prints UNNOTICED, which reads as "this guard is untested" rather than "something moved the file under me". On 2026-08-07 that cost about an hour. Two consecutive sweeps reported the same row UNNOTICED, and every isolated re-check of that row — including driving the harness's own `check()` on it — returned NOTICED. A `__pycache__`-staleness theory was constructed, tested by deleting the cache, and **falsified**; the actual cause was that both sweeps had been run in the background while foreground commands touched the same files. **Amended 2026-08-07 (same day, later session): the acquitted theory was real after all, as a SECOND and independent mechanism** — the pytest witness genuinely does read stale bytecode when two rows touch one file inside the same second (measured: identical 14-byte size, mtimes `…352.32` and `…352.78`, the mutated module read as unmutated), and it is now closed by `-B` on the harness's pytest argv (`no.md` #16). Deleting the cache falsified it *that* time because the collision is a race and had not occurred in the run being examined. The correction matters more than the fact: **a theory tested once and acquitted is acquitted for that run, not for the class** — and the two mechanisms here are indistinguishable from the outside, since both print UNNOTICED for a guard that works. A clean foreground sweep with nothing else running returned 54/54 NOTICED with a byte-identical restore. The harness refuses to *start* on a dirty tree, which shows the authors knew tree ownership matters — but it holds that as a precondition, not an invariant, so a mid-run write is invisible to it (CTS-8795E0FE proposes per-row hashing or a dedicated worktree). Until that lands the rule is operational: start the sweep in the foreground and wait, or give it its own worktree per CLAUDE.md rule 5. **And the wider lesson, which is the one that actually cost the hour: when a verification tool contradicts a direct measurement, suspect the apparatus before the subject — the same failure recorded one session earlier, when a deleted `output-file-map` was read as a test verdict for several turns.** Decided 2026-08-07.

15. **No absolute SLO 1 assertion on a shared CI runner, and no widened budget to make one fit.** `testPerformCycleMeetsTheSLO1Gate` asserted p50 < 70 ms everywhere. On GitHub's macOS runner the p50 for **unchanged** code across five consecutive `main` runs was 119.9 / 86.6 / 96.6 / 86.0 / 74.2 ms — a 62% spread bracketing the gate from both sides — while the same commits measured 48.45 ms locally in isolation *and* passed the full 357-test suite under `swift test --parallel`, i.e. under maximum local contention. The gate returned FAIL for a busy neighbour and PASS for the same code minutes later, so it could not fail for the reason it existed. Its message made this worse by asserting the opposite ("the median is load-stable, so this is a real regression rather than contention") — a sentence five CI runs had already falsified, and a gate that misdescribes its own failure teaches its reader to discount it. This is the **p95 decision applied one metric short**: p95 became record-only after moving 56.7 → 106.7 ms purely with contention; the median is load-stable *on one machine*, which justifies gating it locally, but it is not comparable *across* machines. So p50 is now asserted on developer hardware and recorded on a shared runner, and the CI lane still runs every assertion that proves the benchmark RAN (sample count, finiteness, per-cycle PASS, non-empty delta) — a benchmark that silently stopped is still a hard failure in both. **Enforcement moved, it did not weaken**: `stage_runtime_bench` runs this same test pre-push on developer hardware, gates the median at 70 ms, and fails closed when the `SLO1-PERFORM` line is absent. Verified in all four quadrants by planting a real latency regression (settle floor 0.030 → 0.060): dev lane FAILS at p50 85.46 ms, CI lane PASSES and records; on healthy code both pass and each prints its line. The lane is spelled ONCE as `assertsP50Locally`, because two inline `if Self.isSharedCIRunner` checks would be two places to invert and reverting either alone would leave the other's test green — the two-cooperating-lines shape that made a Wave 4 guard UNNOTICED by construction. **And the witness is `testTheP50GateIsAssertedOnDeveloperHardware`, which reads the CONSEQUENCE rather than the predicate**: asserting `XCTAssertFalse(isSharedCIRunner)` would pass whichever way the `if` branches, since inverting it leaves the property untouched (`no.md` #12 again). Decided 2026-08-07 (CTS-2D400CAA, diagnosed by a prior session that deferred the edit for want of a local red; the red was then produced by planting the slow floor with `CI=true`, p50 82.01 ms).

16. **No mutation row for the `-B` flag on the harness's own pytest argv, and no wrapped-line anchor to force one.** `run_named_test` passes `-B` so a pytest witness compiles the source the harness just wrote instead of reading `__pycache__`. Every guard here gets a mutation row (CLAUDE.md rule 6), and this one cannot have one. A `Mutation`'s `old=` must quote the text it replaces; the only text identifying that flag is the argv itself; the catalog lives *inside* `mutation-check.py`, so the row's own string becomes a second occurrence and `--verify-targets` refuses it — correctly, since the harness could not say which of the two sites it broke. Three progressively narrower one-line anchors all self-matched. A line-spanning anchor (the technique the other three `mutation-check.py` rows use, where indentation and `\n` make the target unquotable) does work — but only against a wrapped call, and `ruff format` collapses that wrap back to one line immediately, so the row would rot on the next format run rather than fail loudly. The guard is covered by `test_a_mutated_module_is_not_served_from_stale_bytecode`, whose control was run **by hand in both directions**: red with `-B` removed, green with it present. That is exactly what a mutation row would have proven, minus the automation. **The defect it closes is worth stating, because it is the expensive direction:** six pytest rows target `scripts/verdictui-pm.py` in sequence, CPython validates its bytecode cache on mtime *plus size* at one-second granularity, and two rows landing in the same second make the witness judge the *previous* row's compile — so a working guard reports UNNOTICED, which reads as "untested" and invites rewriting correct code. Measured 2026-08-07: exactly one of six went UNNOTICED in a full sweep and NOTICED when re-run alone; the mechanism was then reproduced directly (same 14-byte size, mtimes `…352.32` and `…352.78`, mutated module read as unmutated). **The general rule: a catalog that lives inside its own subject cannot name that subject's code without matching itself — and when the only available anchor is one a formatter will rewrite, an honest hand-run control beats a row that will silently go stale.** Decided 2026-08-07.

17. **No timing assertion in a Codex repair sandbox, and no negative-control-free marker guard.** `no.md` #15 split the SLO 1 p50 lane — asserted on developer hardware, recorded on a shared runner — and enumerated that lane as `CI` plus an explicit `VERDICTUI_RECORD_TIMING_ONLY` override. A **Codex repair sandbox** (`CODEX_CI=1`, `CODEX_SANDBOX=seatbelt`) is a fourth member of that same class and was in none of them, so it was treated as developer hardware and asserted a median it cannot hold: measured 2026-08-09 at **p50 167.50 ms and 394.97 ms** against the 70 ms budget, on source that measures ~49 ms locally. That produced three P1 tickets (CTS-19EEF979, CTS-2CD56051, CTS-3FD84961) describing a latency regression that does not exist — the expensive failure mode #15 already names, since a gate that fails for the environment teaches its reader to discount it. The markers now live in ONE tuple, `CONSTRAINED_TIMING_ENV_MARKERS`, read by the PM, and mirrored by `isSharedCIRunner` in the Swift lane. **The finding worth keeping is not the marker list; it is what the marker tests could not see.** Each new test asserted that a marker turns record-only ON, and every one of them is satisfied by `return True` — measured directly: with the guard replaced by `if True`, the **full Python suite passed 199/199**. Record-only everywhere means the p50 budget is enforced *nowhere*, on every host, while the suite reads green — a gate that has stopped being a gate with no test able to notice. This is `no.md` #12 in its purest form: an assertion satisfied identically by the correct and the broken implementation is not a weak test, it is not a test. Closed by `test_unmarked_writable_host_still_asserts_its_timings`, the negative control — an unmarked host with a writable SwiftPM cache must assert its timings — verified in both directions (passes on correct source, exit 1 on the mutation, byte-identical restore) and pinned by a mutation row so the direction that matters cannot silently disappear again. **The general rule: a predicate whose tests only ever exercise the TRUE branch cannot distinguish a working rule from one that is always true, and when that predicate decides whether a budget is enforced, the always-true form disables the budget everywhere and reports success.** Decided 2026-08-09.

18. **`no.md` #12 is CLOSED — the settle-timeout `settleMs` test exists, and what unlocked it was the FIXTURE, not the assertion.** #12 recorded four failed attempts and concluded the timeout path was unpinnable; it was wrong about the reason, which is why the fifth attempt succeeded. Two things were missing at once. **First, the discriminator.** `> 0` and `<= elapsedMs` are satisfied by a budget as readily as by a measurement, so any test built on them passes against both implementations. The separating fact is the **overshoot**: a settle that gives up at its deadline has, by then, spent strictly MORE than the deadline — it must notice the expiry and unwind — while an implementation echoing the budget reports exactly `150.0` for a 150 ms budget and can never exceed it. Measured before it was asserted: 150.65 ms against 150 ms and 600.59 ms against 600 ms; under the budget-echoing mutation, exactly 150.0 and 600.0, and the test fails naming both. **Second, and this is the half #12 never diagnosed: every prior attempt was exercising a DIFFERENT PATH than its name claimed.** They used `PerpetualMotionScenario`, a layout that moves from the start — and `perform` calls `currentTree()` *before* the settle, which carries its own 3 s deadline and **throws** against a layout that never settles. So the run took the host-error branch, and the number under test was 3002 ms of capture cost against a 120 ms budget. #12 recorded that 3000-vs-120 measurement and read it as "`.custom` does not reach the settle"; the real cause was the capture in front of it, which no change of action could fix. The fixture had to be static until acted on: `LateMotionScenario` settles cleanly on the first capture and starts moving only on the tap, so the settle *after* the act is the one bound by the caller's deadline. **The general rule, and it generalises past this test: when an assertion cannot be made falsifiable, suspect that the fixture is not reaching the code under test before concluding the property is unpinnable — a test whose name says one path and whose fixture reaches another is not weak, it is aimed somewhere else, and every assertion you add to it will keep passing for the wrong reason.** Decided 2026-08-09 (CTS-8DDE6D09 item 2; supersedes `no.md` #12's conclusion, not its analysis of why the obvious assertions fail).

19. **No file-scope split of `ProbeLayoutTests.swift` that widens its fixtures, and no rename-to-fit.** The file is 999 lines against an 800 advisory limit (CTS-D408B8FC), and the obvious split — fixtures into `ProbeLayoutFixtures.swift`, tests staying put — was attempted and **reverted on compiler evidence**. Swift has no cross-file-but-not-cross-target access level: `fileprivate` reaches one file and the next level up is `internal`, which reaches the whole target. So the split requires widening **12 top-level `private` declarations** at once, and the compiler then reports `invalid redeclaration of 'HeadlessHost'` — because `VerdictUIProbeTests.swift` declares its **own** `private final class HeadlessHost<Content: View>` (verified: both files, `private`, identical name). The two coexist *only* because `private` confines each to its file. **That is the finding: `private` here is not stylistic, it is what lets sibling test files own same-named fixtures independently, and a line-count-driven split silently converts that into a namespace collision.** The available workarounds are all worse than the 199 extra lines: renaming one `HeadlessHost` makes two things with one job answer to two names, and nesting the fixtures inside an enum adds a qualifier to every call site in 686 lines of tests to satisfy an advisory threshold. The limit exists to keep files readable; this file is already sectioned (`// MARK:` — headless host, frame measurement, bounds observation, tests) and its length is 12 fixtures plus one coherent suite, not sprawl. **The general rule: a size limit is a proxy for readability, and when the mechanical fix to the proxy makes the code worse, fix the readability instead and record why the number stands.** Revisit if `ProbeLayout` grows a genuinely separate subject — then the split follows a real seam and carries its fixtures with it. Decided 2026-08-09 (CTS-D408B8FC).

20. **`no.md` #16 is CLOSED — the `-B` guard has a mutation row now, and getting one was a side effect of splitting the catalog out of the harness.** #16 recorded a guard that could not be rowed: a `Mutation.old` must quote the text it replaces, the only text identifying the `-B` flag is the argv itself, and the catalog lived *inside* `mutation-check.py`, so the row's own string became a second occurrence and `--verify-targets` refused it — correctly, since the harness could not say which of the two sites it had broken. Three progressively narrower one-line anchors all self-matched; a line-spanning anchor worked only against a wrap `ruff format` immediately collapses. The conclusion drawn was "an honest hand-run control beats a row that will silently go stale", and that was right *given the file layout*. **What #16 never questioned was the layout itself.** Splitting the catalog into `mutation_catalog.py` for size (CTS-47AA0547) removed the constraint entirely: two files that do not contain each other's text can quote each other freely, so `old='return run([sys.executable, "-B", "-m", "pytest"'` now matches exactly one site. Row added, hand-verified NOTICED (exit 1 on `test_a_mutated_module_is_not_served_from_stale_bytecode`) with a byte-identical restore, and `--verify-targets` reads 64. The narrower rule that replaces it: **a catalog may not quote text from the file the catalog itself lives in** — rows targeting `mutation_catalog.py` would self-match there for exactly the same reason, which is now a small and clearly-bounded exclusion rather than a hole over the whole harness. **The general rule: when a guard is "impossible to test", check whether the impossibility is a property of the guard or of where the code happens to sit — a structural constraint that looks intrinsic is often just a file boundary nobody had reason to move.** Decided 2026-08-09 (CTS-47AA0547; supersedes `no.md` #16's conclusion, not its analysis of why the self-match occurs).

21. **`no.md` #14's operational rule now has a mechanical half — a row whose file is written mid-run ABORTS rather than scoring.** #14 recorded that a concurrent write during a sweep corrupts the verdict *silently in the expensive direction*: the harness prints UNNOTICED, which reads as "this guard is untested" and invites rewriting correct code, and it cost about an hour on 2026-08-07. The harness already hashed the file before and after the RESTORE, so it could detect a botched restore — but that check runs after the row is scored, and `main`'s clean-tree check is evaluated *between* rows. Neither can see the window that actually matters: the test run itself, which is where all the time goes. `check()` now records the sha256 of the mutated content it wrote and re-reads it after the witness returns; a mismatch exits 3 naming the file, instead of classifying a result produced against a tree nobody intended. **The mutation output is the argument for it**: with the guard removed, the harness prints `NOTICED` for a row whose subject had been rewritten mid-run — a confident verdict about the wrong bytes, indistinguishable at the point of use from a real one. The control (an untouched file still produces its verdict and restores) is what stops "aborts on meddling" being satisfied by a harness that aborts on everything. **This does NOT retire #14's operational rule** — the guard converts a silent wrong answer into a loud refusal, which is strictly better but still a stopped sweep; running in the foreground on an exclusive tree remains how you get a *result*. **The general rule: a precondition checked once is not an invariant, and the gap between the two is exactly the interval where the expensive work happens.** Decided 2026-08-09 (CTS-8795E0FE).

22. **No split of `verdictui-pm.py` that moves `_pm_log` out of it, and no chasing the 800-line advisory across the three files now sitting just over it.** The obvious extraction — the Swift toolchain layer (lock files, zombie processes, the timing lane, the streaming runner; ~206 lines) into `verdictui_swift_runner.py` — was **built and reverted on test evidence**. It compiled and the import shim was clean, but 25 tests went red, and the instructive one is `test_pm_log_routes_through_logging`: `_pm_log` uses `logging.getLogger(__name__)`, so moving the function **changes the logger name every PM record is emitted under**, from `verdictui_pm` to `verdictui_swift_runner`. That is not a test needing an update — it is a real change to what the PM's log output looks like to anything that filters by logger, and the test was correctly reporting it. A file-size refactor that silently re-labels every log record is not a refactor. **The three files this session left just over the line are 923 / 878 / 814 against 800**, and each has the same shape of reason: `verdictui-pm.py` is 20 stages with no seam that does not move a logger or thread a dozen constants; `mutation_catalog.py` is a flat list of 67 rows whose only possible cut is an arbitrary row number (`no.md` #20); `test_mutation_check.py` is one subject — the harness — tested from several angles. **The 800 figure is a fleet CEO-audit heuristic and is not enforced by this project's PM** (verified: nothing in `verdictui-pm.py` or `floor-check.py` reads it), which is the right level for it, because it is a proxy for readability rather than a contract. Where the proxy and the thing it proxies disagree, the thing wins. **The general rule, and it is the same one as #19: when the mechanical fix to a size limit makes the code worse — a re-labelled logger, a renamed fixture, an arbitrary cut — take the readability win you can get (sections, docstrings, honest boundaries) and record why the number stands, rather than shipping a worse file with a better line count.** Decided 2026-08-10 (CTS-7AEBCC56, CTS-46EF20D6, CTS-0D2246C8).
